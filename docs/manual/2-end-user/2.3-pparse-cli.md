## 2.3 `pparse` CLI

`yannt pparse` or `pparse` are the commands you can run to parse supported files from the command line. Available `pparse` subcommands are dependent on what pparse plugins are installed into the current Python environment. Many of the `pparse` plugins are built into `pparse` itself and therefore require no extra install commands.

At the time of this writing, `yannt pparse --help` prints:

```sh
usage: yannt pparse [-h] [--breakpoint] [-v] [--log-level MODULE:LEVEL]
                    {flatbuffers,ident,json,mnn,om,onnx,pickle,protobuf,pytorch,safetensors,tflite,xml,zip}
                    ...

positional arguments:
  {flatbuffers,ident,json,mnn,om,onnx,pickle,protobuf,pytorch,safetensors,tflite,xml,zip}
    flatbuffers         flatbuffers command
    ident               ident command
    json                json command
    mnn                 mnn command
    om                  om command
    onnx                onnx command
    pickle              pickle command
    protobuf            protobuf command
    pytorch             pytorch command
    safetensors         safetensors command
    tflite              tflite command
    xml                 xml command
    zip                 zip command

optional arguments:
  -h, --help            show this help message and exit
  --breakpoint          breakpoint() after operation
  -v, --verbose         Increase verbosity
  --log-level MODULE:LEVEL
                        Example: --log-level thirdparty.yannt:DEBUG
```

<div class="h4-style">Safetensors Example</div>

Each of the positional arguments are the CLI registered format parsers. If you want to see what actions are supported with a specific format, use `--help` with the subcommand:

```sh
# yannt pparse safetensors --help
usage: yannt pparse safetensors [-h] {view,index,header,pheader,hash} ...

positional arguments:
  {view,index,header,pheader,hash}
    view                safetensors view command
    index               safetensors index view command
    header              safetensors header command
    pheader             safetensors header command
    hash                safetensors hash command

optional arguments:
  -h, --help            show this help message and exit
```

In the case of safetensors, there is:

- `view` - The conventional subcommand to parse a safetensors file and optionally print to STDOUT with `--print`.
- `index` - Subcommand to parse a sharded safetensors collection and optionally print to STDOUT with `--print`.
- `header` - Extract safetensor's JSON header as JSON.
- `pheader` - Extract safetensor's JSON header as pparse node tree.

<div class="h4-style">Launching PDB Prompt</div>

As mentioned in the primers section, you can often launch PDB by adding `--breakpoint` to the CLI command. `--breakpoint` is a pparse argument so by convention you put it before the format subcommand:

```sh
yannt pparse --breakpoint safetensors header /path/to/model.safetensors
```

<div class="h4-style">Dumping More Log Output</div>

When troubleshooting or inspecting weird behavior of pparse, you can enable more output by adjusting the logging level. The log level is adjusted by adding `-v` as arguments to `pparse`. The more you add, the more verbose (up to 7). If there is a specific logger (i.e. module) that you want logging on, you can use the `--log-level` argument to specify the specific log level for that module.

Example `--log-level`:

```sh
yannt pparse --log-level thirdparty.yannt:DEBUG header /path/to/model.safetensors
```
