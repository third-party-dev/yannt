### Protobuf Use Cases

Several model formats use protobuf. The normal protobuf parsing process involves running a code generator and then using the generated code to deserialize the data structures. This is insufficient for forensic parsing. Therefore pparse uses a protobuf descriptor file to parse relevant protobuf streams. This interface has been made generic with situations where you may have a protobuf stream that is not currently associated with some other pparse parser type.

<div class="h3-style">Use Case Synopsis</div>

- Parse protobuf stream with protobuf descriptor and root msg type.

<div class="h3-style">Use Case: Parse protobuf stream with protobuf descriptor and root msg type.</div>

If you only have the proto files and assuming you can acquire a protobuf compiler (`protoc`), you can build a protobuf descriptor file from the proto files with:

```sh
protoc --proto_path=. --descriptor_set_out=onnx.pb --include_imports onnx.proto3
```

The default message type is something you must inherently know. The convention for an ONNX file is to use `.onnx.ModelProto` for the root message type.

Note: Based on how the current protobuf parser is implemented, you must suffix the protobuf file to be parsed with `.pb`.

Knowing the protobuf descriptor file (e.g. onnx.pb), the root message type (e.g. `.onnx.ModelProto`) and the protobuf encoded model file path (suffixed with `.pb`), we can now parse the protobuf stream with:

```sh
yannt pparse protobuf parse ./model.pb ./onnx.pb .onnx.ModelProto
```

You can do the same with `breakpoint()` for runtime inspection.

```sh
yannt pparse --breakpoint protobuf parse ./model.pb ./onnx.pb .onnx.ModelProto
```

If you want to see everything at once with an editor:

```sh
yannt pparse protobuf parse --dump model-dump.txt ./model.pb ./onnx.pb .onnx.ModelProto
```

Recommended to use `Ctrl+K`,`Ctrl+0` to fold up `model-dump.txt` in VSCode and then only expand what you want to expand. (The file is VERY long.)
