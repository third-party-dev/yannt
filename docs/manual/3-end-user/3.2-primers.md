### Python Debugger (PDB)

As a forensic tools, there are many situations where we need to dig into a specific data structure or raw data at an offset stored in a data structure. One of the quickest ways to accomplish this is with the Python Debugger. By convention, pparse and yannt often allow the python debugger to be executed after the CLI command is run, but before the process is exited. The PDB prompt is a lost cost way that allows a CLI user to use simple python statements to inspect the state of data structures in Python memory. The PDB prompt is enabled by using the common `--breakpoint` argument.

### Common Shell Usage

Inspired by the old Unix adage that tools should do one thing and do it well, yannt/pparse have been developed with CLI STDOUT operations in mind. By convention, nearly all pparse commands have the option to dump or print its output to STDOUT in a machine-readable and human-readable format with the `--print` argument. The output being both machine-readable and human-readable enables the use of piped commands to analyze and hunt for desired artifacts using tools like:

### XML & JSON Viewers

pparse can generate very large output. Looking at 500K lines of XML or JSON will quickly become overwhelming. When faced with large structured files like these, you can limit what you want to look at by utilizing the folding feature of the viewer. For example, use `pparse` to parse a model into an XML file. When you open the XML in VSCode, push Ctrl+K Ctrl+0 on the keyboard to fold up all parts of the file. Once everything is a single element, you can methodically only unfold sections of the data that you want to drill down into.
