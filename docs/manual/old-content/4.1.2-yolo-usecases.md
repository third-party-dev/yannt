# Yolo Use Cases

## Overview

To clarify, I do not have anything to do with upstream Ultralytics implementation. That said, I do require use of the ultralytics' `yolo` package to generate test data for various yolo formats. Therefore, there are a few use cases that I try to ensure users can run adjacent to the yannt environment.

Ultralytics incorporates an impressively diverse number of ML libraries in support of their yolo models. The best way to utilize everything from a single source, I recommend their `python-export` docker image. Acknowledging that docker is not always available for all data science environments, yannt also maintains conda and podman environments for Ultralytics. The conda version is sort of hodgepodge and therefore not as good as the `python-export` container image, but close enough.

## Installation

Ultralytics combines capabilities from many different ML environments. These different libraries rarely place nice together and therefore it can be a frustrating time getting them all into a single environment. I've personally run through a bit of a gambit to get things to the working state that they are and its "good enough" for me at the moment.

- `yolo-conda` - Process that will build a conda environment with ultralytics installed and will install every yolo export dependencies known to me (except tensorflow).
- `yolo-tf-conda` - A special environment for handling Tensorflow based models (tflite, saved_model).
- `yolo-docker` - An `docker.io/ultralytics/ultralytics:8.4.8-python-export` docker based container install. It has all the things ready to go, but locked in at verion 8.4.8 and several years old. (Looked at source and while the `python-export` is still in code, appears to not be regularly tested?)
- `yolo-podman` - An `docker.io/ultralytics/ultralytics:8.4.8-python-export` podman based container install for those without docker access.

Note: None of these have been tested with GPU exports yet. In theory, the docker setup would work with GPU exports if you volume mounted the correct paths from host. This is on my things "to do", but hasn't happened yet.

## Environment Setup

From the top project folder of yannt, you can run one of the following depending on your environment's permissions:

- `./do init yolo-docker -- bash` - Initialize the environment for docker usage.
  - `./do run yolo-docker -- bash` - Re-run if already initialized.
- `./do init yolo-conda` - Initialize the environment for conda usage.
  - `./do run yolo-conda` - Re-run if already initialized.
- `./do init yolo-podman -- bash` - Initialize the environment for (usermode) podman usage.
  - `./do run yolo-podman -- bash` - Re-run if already initialized.

Once the environment is up an running, you'll know its working because you can run the following command `yolo export help` without python exceptions. Example:

## Run Yolo With Short Lived Container

In the case of docker and podman, you can run yolo without starting a long-lived container.

```sh
./do init yolo-docker -- yolo export help
```

or

```sh
./do init yolo-podman -- yolo export help
```

## Ultralytics models

When you specify `model=` argument value as a file on disk, it will read the file on disk. If it is not a file on disk, the `yolo` command will attempt to automatically download the model from its upstream repository of PyTorch yolo model checkpoint files.

- [8.4.0 Released Assets](https://github.com/ultralytics/assets/releases/tag/v8.4.0) (circa Jan 2026)
- [8.3.0 Released Assets](https://github.com/ultralytics/assets/releases/tag/v8.3.0) (circa Sep 2024)
- [8.2.0 Released Assets](https://github.com/ultralytics/assets/releases/tag/v8.2.0) (circa Apr 2024)
- [8.1.0 Released Assets](https://github.com/ultralytics/assets/releases/tag/v8.1.0) (circa Jan 2024)
- [Initial Released Assets](https://github.com/ultralytics/assets/releases/tag/v0.0.0) (circa Jan 2023)

- Convert yolo model to TorchScript

- Convert yolo model to TFLite

NOT TESTED

- Convert yolo model to TensorRT (engine)
